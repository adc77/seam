# Developer v1: use the SDK before expanding it

The Seam 0.10.0 runtime and core APIs are frozen for this milestone. This is a usable
developer v1, not a 1.0 release, API-stability promise, or calibrated agent society.
Glass 0.6.1 packages the first consumer-facing demo; it still pins the same SDK code.

## Start here

Follow [Glass's quickstart](https://github.com/adc77/glass/blob/main/QUICKSTART.md).
Its installed `glass-demo --scripted --out <new-directory>` command executes real product
handlers with isolated synthetic lab dependencies. It pairs healthy/faulted conditions,
persists one external decision, continues in a fresh process, opens verified viewer evidence,
and checks two byte-identical provider-free replays of every run.

The controller is explicitly scripted, not an LLM. It needs no GPU or API key and makes
no paid calls. Real-model integration remains optional and explicit through the
[provider-neutral controller](INFERENCE_EXPERIMENTS.md). See the separate
[real-persona validation report](https://github.com/adc77/glass/blob/main/PERSONA_VALIDATION.md)
for the existing runtime successes and goal failure. Never equate replay correctness
with realistic human behavior or successful reasoning.

## Independent adoption: a synthetic helpdesk

A separate local package, `seam-helpdesk-example` 0.1.0, adopts the published frozen
SDK commit `89388917628431e571f02afbd1fd9d121be8b1f1`. It imports neither Glass nor
Reservations. Its source remains local; this is recorded local evidence, not a publicly
reproducible third-product release. No organization systems or production data are used.

The product owns a finite-worker FIFO queue, service-completion timers, customer
abandonment, and an idempotent notification adapter. Impatient/patient synthetic customers
see their own ticket and an aggregate queue depth, not other customers' identities.
Legal action choices and patience eligibility are product code, not model instructions.

| Paired condition | Resolved goals | Abandoned requests | Stored notifications |
| --- | --- | --- | --- |
| Healthy: two workers, one-second service | 2 | 0 | 2 |
| Scarce: one worker, four-second service, lost acknowledgements | 1 | 1 | 1 |

Both conditions pass software checks. Abandonment still counts as an unsuccessful goal.
Stale timers cannot resurrect abandoned work. Notification retries use the original key;
notification failure is reported separately from ticket resolution.

The adoption exercises the same handlers in live mode with a test notification/timer
driver and in supervised simulation, ordinary checkpoint recovery, durable inference
continuation, paired metrics, strict recorded replay, and the read-only viewer. It does
not prove a deployed, crash-durable helpdesk or realistic customer behavior. Two paired
seeds validate a fixture; they do not establish population statistics.

## Verification on 2026-10-13

Fresh installed environments passed both product demos on Python 3.11.14, 3.13.10,
and 3.14.2, without `PYTHONPATH` or sibling checkouts. Each interpreter passed the
full suites: 260 Seam tests, 85 Glass tests, and 13 helpdesk tests. The installed
Glass HTTP/SQLite proof additionally survived three forced process restarts, recovered
its capture, preserved private IDs, replayed byte-identically, and left its live database
unchanged during replay. An actual loopback viewer served both products' HTML and
verified evidence catalog. No paid inference or cloud resources were used for this work.

## What usage actually revealed

No SDK core change was required. The new product fits the current ports, shared worlds,
actors, authorized choices, experiment adapter, and replay contracts.

- The first-run path was fragmented across developer docs and private proof scripts.
  Glass now supplies an installed command and one quickstart, with a CI-installed proof.
- Adapter setup remains manual: module entry point, initial snapshot, dependency schemas,
  observation projection, action translator, choices, and metrics. The integration initially
  used the wrong World accessor and placed a checkpoint outside its case directory;
  correcting the product tests resolved both. These suggest better examples, not new APIs.
- Goals need product-defined outcome metrics. Completing all decisions or delivering a
  notification does not alone imply the customer's goal succeeded.
- Timing, ownership, idempotency, and state validation stay product responsibilities.
  Seam can enforce supplied contracts; it cannot infer business semantics from persona prose.
- Existing prefix reexecution and source-identity restrictions still favor small,
  sequential studies and preserved environments. This adoption does not establish scale,
  journal migration, or compatibility across upgrades.

## Next gate, not another feature list

The fresh-clone usability pass refines documentation, the Glass demo CLI, and the
companion viewer without changing `seam/`. Outcome labels distinguish completed
dispositions from preferred releases; viewer labels distinguish engine checks and actor
decision completion from business success. Friendly path diagnostics never overwrite,
repair, or weaken evidence validation. Existing environments and journals stay preserved.

Let someone outside the implementation run the quickstart and integrate one owned
workflow. Record concrete setup failures, missing observations, awkward adapter code,
or replay problems. Prioritize a v1.1 change only when usage demonstrates its need.
Better goal reasoning, larger mixed populations, migration tooling, and throughput
improvements remain candidates, not automatic expansion of the frozen core.

The [integration guide](ADOPTING.md) and [copyable product starter](examples/starter/README.md)
now provide that handoff. The starter is its own package pinned to the existing published
SDK, not new code inside `seam/`. Its finite-stock example exposes a failed buyer goal,
lost-acknowledgement idempotency, pending work, and strict recorded replay. Independent
feedback remains a separate acceptance gate; our own fresh-copy tests do not satisfy it.

The separate [developer companion](tools/adoption/README.md) adds opt-in project generation,
installed-source/prepared-input preflight, explicit rule runs, and the existing read-only
viewer. It reuses the tested order starter and the unchanged published SDK. It does not
implement autonomous exploration, a Glass product UI/browser bridge, or larger-population
studies. Independent developer feedback is still outstanding.
