# Offline reactive actors

The separately reviewed [external inference increment](INFERENCE.md) adds an explicit response-prefix protocol. The rule/replay behavior below remains the offline contract.

Seam 0.5 adds an optional `seam.actors` module. A persona can observe a product, choose an authorized action, remember its result, and act again. Product handlers and dependency adapters still own business rules.

This first increment is offline and synchronous. It provides scripted/seeded Python policies, recorded decisions, private JSON memory, deterministic wakeups, and checkpoint recovery. It does not provide LLM inference, a UI, notification subscriptions, or editable checkpoint forks.

## Integration

```python
from seam.actors import ActorSystem, population

system = ActorSystem({"customer_v1": decide}, observe, translate)
system.install(runtime)

data = population([
    {
        "id": "alice",
        "policy": "customer_v1",
        "profile": {"goal": "book", "patience_ns": 100},
        "memory": {"phase": "start"},
        "actions": ["reserve", "cancel"],
        "start_ns": 0,
        "max_decisions": 20,
    }
], seed=77)
```

The callbacks are product-owned synchronous functions:

- `observe(actor, product_state_copy, at_ns)` returns only approved actor-visible JSON. `actor` contains `id`, `profile`, and that actor's private `memory`. It receives no runtime/context and cannot mutate the supplied product state in place.
- `decide(request_copy, rng)` returns `{"action": ..., "memory": ..., "wake_after_ns": ...}`. `action` is null or `{"type": ..., "body": ...}`. A null wake delay finishes that actor; an integer delay schedules its next observation/decision. `action: null` plus a delay means wait.
- `translate(actor_copy, action_copy, decision_id)` validates domain schema and ownership, then returns `{"handler": ..., "body": ...}`. The supplied stable `decision_id` can be the product's idempotency key. Actor action names never directly select handlers.

The decision request contains `actor_id`, `policy`, `step`, `at_ns`, `profile`, `memory`, `observation`, `rng_before`, `seed`, and the allowed `actions`. Use a versioned policy identifier such as `customer_v1`. JSON inputs are copied, and accepted memory is copied and persisted separately from product state.

The SDK enforces the actor's action allowlist. The adapter must additionally enforce record ownership and action-specific authorization. Python callbacks are trusted code, not a sandbox against hostile Python introspection.

Store `data` in a hashed v3 dataset. Add this ordinary world/port plan:

```json
{
  "worlds": {"actors": {"dataset": "population"}},
  "ports": {"actors": {"mode": "world", "world": "actors"}},
  "arrivals": [
    {"at_ns": 0, "handler": "actors_start", "body": {}},
    {"at_ns": 100, "handler": "actors_finish", "body": {}}
  ],
  "same_time_order": "timers_first",
  "stop": {"when": "deadline", "deadline_ns": 100, "allow_quiescence": true}
}
```

This fragment must be combined with the product's own ports, worlds, bootstrap, state, and complete case fields. Actors can see product state projections; the product must publish observable outcomes in that state after its handlers run.

Initialization schedules the population in input order. A decision queues its translated product handler at the current virtual time, then queues its next decision. There is no nested delivery or independent actor thread. `timers_first` lets pending actor/product work at the horizon execute before the finalization arrival. Actor rules follow the selected case scheduling policy; existing v1/v2/v3 behavior is unchanged.

`actors_finish` seals decisions and refuses eligible pending actor decisions or unused replay entries. Use a declared deadline when future wakeups remain; sealing is not a command to run future actors. Missing finalization leaves `world_states.actors.sealed` false even if the ordinary case reports success. Experiment controllers must require both a passed supervised artifact and a sealed actor world before reporting a completed experiment.

Install this module in a separate simulation entry point. Actor activation in live mode faults with `actor_live_forbidden`; ordinary production entry points do not need to import it. `name=` can choose a distinct port/world/handler prefix; names must leave room for the handler suffixes.

## Data, randomness, and bounds

Population format is `seam-actors`, version 1. Every field in the example is required. The dataset also contains explicit `seed`, `mode`, and `tape` fields generated by `population`. Unknown fields, duplicate IDs/actions, invalid times, and non-Seam JSON fault instead of silently choosing defaults.

Each actor uses `SHA256("seam.actors.v1:<seed>:<actor_id>")`, takes its first eight bytes as a little-endian seed, and uses Seam's counter RNG. Population seeds are nonnegative signed-64-bit integers. Actor streams do not consume the product RNG or change when another actor is added.

Limits are 100 actors, 1,000 accepted decisions across the world, up to 1,000 per actor, 32 allowed action names per actor, 1,024 RNG draws per decision, and 1 MiB canonical actor dataset/state/individual decision data. Product-specific limits can be tighter. Normal event, port-call, dataset, artifact, and supervision limits also apply. Zero-delay loops exhaust a budget; they never become a misleading successful experiment.

Observations cannot see other actors' private state unless a trusted adapter explicitly leaks it. Full controller artifacts do contain private memories and decision traces; they are not safe for public sharing. Use access-controlled directories and product-owned sanitization. Rules have no permission to call network clients or real clocks; the usual handler guards remain active.

## Recorded replay

```python
tape = completed_artifact["world_states"]["actors"]["decisions"]
recorded_data = population(original_actor_specs, seed=77, tape=tape)
```

Passing an explicit tape, including an empty list, selects replay. Policies are registered for identity validation but are not executed. The complete request must match, including the observation, memory, time, step, profile, and RNG cursor. Translated delivery must also match after the adapter validates it. Exhaustion, mismatch, and unused entries fault; no fresh decision or live-call fallback exists.

Replay consumes the accepted memory/action and RNG cursor from the record. This reproduces a particular recorded trajectory; it does not simulate how users would respond to different observations. Changing a product policy requires a fresh reactive run, not reusing mismatched decisions.

Two identical replay cases produce byte-identical artifacts in the same controlled environment. An exploration case and its recorded replay have different dataset/case/world provenance, so their full digests need not match; compare domain outcomes and accepted decision records. Existing ordinary `tape_from_artifact` is a port tape and is not an actor decision tape.

## Recovery

Opt-in [choice policies](CHOICES.md) record both the selected intention and its trusted
resolution. Their restore path also revalidates the menu, resolution, and translated
delivery. The legacy behavior below remains unchanged.

Actor state is a shared `World`, not hidden state in a callback closure or a product-state key. Existing v3 checkpoints already preserve its initialized snapshot together with the product, other worlds, scheduler queue, and pending timers.

Restore validates population identity and reconstructs the actor memory/counter/wakeup state from accepted records without re-executing policy or translation callbacks. Per-actor step/observation requests reject duplicate or stale wakeups. Repeated fresh-process resumes preserve behavior digests and full history, although checkpoint/case provenance identifies the different operational inputs.

Only completed-handler boundaries are checkpointable. An interrupted uncheckpointed segment can be rerun from the last valid checkpoint because simulation dependencies are isolated; arbitrary live external effects are not covered. Product adapter idempotency remains necessary for any persistent effects.

Resume is the same workload. Changing a population, tape, config, source, environment, or input refuses under ordinary checkpoint identity rules. There is no counterfactual checkpoint mutation or cross-build migration API.

## Proofs and adoption

`seam.proof.actors` is a small domain-neutral counter product used by `tests.test_actors`. Tests cover strict schemas, permission and budget failures, replay mismatch/exhaustion/unused entries, policy-copy isolation, independent RNG, horizon sealing, overflow, and repeated checkpoint resumes.

Reservations and Glass have independent actor adapters and separate simulation entry points. Their CLI/tests use the actual reservation/sample handlers; the SDK knows neither domain. All personas/data are synthetic assumptions, not validated behavioral predictions.

This is an unreleased feature branch. Build/install the matching SDK wheel before testing actor consumers locally. Do not claim their existing main dependency pins provide actor support; pin a tested, remotely available full SDK commit before publishing dependent consumer PRs. Existing source-pinned captures/journals require their original product/SDK environment; adding Python modules changes source identity even if ordinary business handlers are unchanged.
